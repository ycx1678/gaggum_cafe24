# 추가 구성품 견적 옵션 복구

## 범위와 원인

신고 조합은 상품 1034 수량 62, 상품 138 수량 3, 추가 구성품 465 수량 3이다. 465는 단독 공개 상세가 404지만 138의 `add_option_data`에 `P00000RX000A`가 제공된다. v187은 장바구니에서 해당 단독 페이지만 조회하고, 상품 선택 시에는 본상품의 mapper를 사용하여 추가품 코드를 놓쳤다.

스킨의 기존 라이브 커밋 407cb59를 기준으로 v188만 추가한다. 원격 main은 라이브보다 오래된 참조를 포함하므로 전체 main 파일을 운영에 덮어쓰지 않는다. 백오피스·상품 설정·고객 데이터는 변경하지 않는다.

## 수정과 검증 경계

- 새 선택에서는 추가품 자신의 공개 옵션 mapper를 저장한다.
- 기존 장바구니에서는 같은 요청에 포함된 본상품의 공개 추가품 메타데이터로 누락 코드를 확인한다. 유일한 본상품과 일치할 때만 추가품으로 연결하며 수량·단가를 보존한다.
- 부모가 없거나 모호한 경우, 옵션 문구 불일치, 다른 상품 코드, 잘못된 JSON은 임의의 옵션으로 대체하지 않는다.
- 확인 경계는 공개 상품 HTML → 실제 JS → 견적 POST payload다. 테스트의 POST는 가로채며 운영 견적·주문·결제·알림을 생성하지 않는다.

## 검사 기록

- 기존 장바구니와 신규 선택 경로를 각각 v187에서 실패 재현 후 v188에서 통과시켰다.
- 실제 1034/138 공개 HTML로 PC·모바일의 1034=`P0000BNU000A`, 138=`P00000FI0BHM`, 465=`P00000RX000A`와 수량 62/3/3, 추가품 부모 순서 1을 확인했다.
- 추가품 9개 검사 + 기존 일반 옵션 10개 + 회원 조회 2개: 21/21 통과.
- 전체 테스트는 22개 통과, 기존 누락 파일 `quote_order_v194.js`로 인한 2개 실패. 기존 배포 기준에서도 알려진 실패이며 이번 수정 대상이 아니다.

## 배포 조건

`nd/js/quote_parent_v188.js`, `layout/basic/layout.html`, `layout/basic/main.html` 세 파일만 배포한다. 원본과 해시를 대조하고 신규 자산 업로드 후 참조만 치환한다. 참조 교체 또는 공개 검증 실패 시 두 참조 파일을 원복한다. 백업은 14일 artifact로 보관하고 FTP secrets 삭제 및 runner archive를 재확인한다.
